# 想拆

> 把想做的事拆成一条能走的步骤路线。纯前端、无后端、无账号，数据只存在你自己的浏览器里。

如果你是 AI / Agent：读完这一页就够了解本项目。文末「给 Agent 的速查」是可直接引用的功能与接口清单。

## 这是什么

一个用来规划工作和生活的行动路线工具。核心就一件事：**一个目标 → 几条并行的方向 → 每条方向下具体的动作**，画成一棵能长期看下去、能拖能改的树。

它没有后端、没有账号、不联网上传数据。打开就用，数据存在浏览器本地。

## 功能

### 路线：一条能一直往下拆的树

- **建树**：一个目标下可以有几条并行方向，每条方向下再拆具体动作，层层往下。
- **拖拽**：卡片可以直接拖走（连同子任务和同一串里后面的步骤一起搬）；拖到另一张卡片上 = 变成它的一条新的并行子任务线；悬停时目标卡出现紫色高亮边框。跨路线拖拽时右栏弹出目标路线结构预览，可以精确选落到哪张卡片下。
- **抽屉内拖动**：子任务列表里可以调整这一串的顺序，或拖到另一条分线的某一行并入那条线（只搬这一张卡 + 它自己的子任务）。
- **删除**：删任务时可「只删这条（后面一步自动接回前一步）」或「连后面整串一起删」。
- **撤回 / 重做**：勾选、删除、拖拽都在同一个「撤回」按钮里，按钮显示下一步撤的是什么；撤销多了可以「回到下一步」救回来。
- **复制粘贴**：右键卡片可复制「这张 + 子任务」或「这一串 + 后面步骤」；右键目标卡粘贴 = 变成并行子任务，右键空白处粘贴 = 成为当前路线的新目标；也支持 ⌘C/⌘V。
- **一键清已完成**：卡片右键可清除它下面整条线都做完的并行线；只要还有没做完的，整条保留不动，可撤回。
- **标记不合适**：卡片右键「这个任务似乎不太合适」——当前卡标红划去，未完成的子任务和后续步骤灰掉，保留记录；可取消、可撤回。把灰卡拖到别的链上（前面没有红卡了）会自己恢复白色。
- **新路线自动命名**：新建路线可以不起名，加了第一个目标卡后路线名自动跟着它；手动改名后停止跟随。

### 卡片里的字段

- **行动目标和目的**：这张卡要达成什么。
- **行动思路**：独立的填写框，在目标和「具体怎么做」之间——写打算怎么走、先试什么、什么情况下换方案。是想法推演，不算交付物。
- **具体怎么做**：具体动作。
- **其他备注**：自由记录，不参与依赖和勾选。
- **正文插图**：以上富文本都能插图，图片可插在任意两个字之间；直接粘贴截图 / 拖图进来即可，压缩后存在本地数据里。正文只显示「图N」小胶囊，悬停放大、点击看全屏。

### 进度与重点

- **进度**：勾过的任务会亮；勾父任务连带勾子任务，勾串行后面一步连带勾前面的；所有勾选都能撤回。
- **重点清单**：点卡片图钉把它钉到页面顶部；钉父任务连带钉上三层以内的子任务。清单汇总**所有路线**的重点，每行可折叠，表头有「全部折叠 / 全部展开」。

### 多路线与整理

- **多条路线**：工作一条、生活一条，随时切换；右栏可新建文件夹归纳，文件夹可折叠 / 删除。
- **路线搜索**：右栏顶部可搜路线名；路线区右上角有固定浮窗搜索框，回车跳下一张卡（Shift+回车上一张），命中卡片自动滚到中间并闪烁；输 5 位码（如 `#BCU5C`）回车直接跳到那张卡或那条路线。
- **路线链接**：把另一条路线实时展开在当前路线里（蓝色描边）；链接卡可拖动、删除、改字段，改动写回源路线。也有「复制路线链接」「独立成一条路线」（原位置内容照旧保留，只是套蓝边同步）。
- **右键菜单不越界**：屏幕边缘的卡片右键，菜单会夹进窗口内。

### 其它

- **外观**：跟随系统 / 浅色 / 深色三档，手动选过就固定住。
- **导出 / 导入 JSON**：换电脑、换浏览器时搬数据。
- **深链**：`?route=<boardId>&node=<nodeId>`（或 `?c=<5位码>`）打开即定位到那张卡，方便从笔记里跳回来。
- **打开状态记忆**：右栏路线列表记住上次是展开还是收起。

行动路线**不导出 Markdown**——串行/并行关系用 md 表达不清楚也导不回来，JSON 是唯一数据格式。

## 跑起来

```bash
npm install
npm run dev        # http://127.0.0.1:5174  开发版
npm run build      # tsc --noEmit + vite build，产出 dist/
```

不需要任何密钥——路线功能全部纯本地。构建产物 `dist/` 可以直接扔到任意静态托管。

## 稳定版一键更新

跑 `npm run stable` 的稳定版（127.0.0.1:5180）会自动检测 GitHub 上有没有新提交：页面右上角的小圆点变亮、显示「有新版本」时，点一下就会拉取 → 构建 → 切到新版；服务端代码有变化时才重启服务，否则刷新页面即可。全程在你的机器上跑，路线数据（`data/`，被 gitignore）不会被覆盖，更新前会备份。

- 小圆点（绿色）= 已是最新，点一下可强制重新检查
- 纯静态部署（没有本地服务）不会出现这个按钮，不影响使用
- 更新卡住可看 `/tmp/work-route-stable.log` 和 `data/update-state.json`
- 前提：本机工作区没有未提交改动；有改动时更新会停下并提示，避免覆盖你正在写的东西

## 数据

- 默认存在浏览器 `localStorage`，key 是 `work-route-actions-v1`，按 origin（地址）隔离。不同端口 = 不同数据。
- 带本地数据 API 时（见下），数据会同时落到项目里的 JSON 文件：
  - 开发版 `data/routes.json`
  - 稳定版 `data/routes-stable.json`
- 换设备用页面右栏「导出数据」→ 新设备「导入数据」。

**码**：每条路线、每张卡都有一个从 id 派生的 5 位码（如 `#9NVDA`）。卡片 hover 会显示、点一下复制。改名、移动、导出再导入，码都跟着同一条数据走；复制出的新卡码会变，删掉的卡码失效。

## MCP：让外部 Agent 读写你的路线

项目自带一个 MCP server（`mcp/`）。任何支持 MCP 的客户端（Claude Desktop / Claude Code / Cursor / WorkBuddy / 豆包等）配上它，就能直接读和改路线——网页会自动刷新，界面外观不变。

这就是本项目的「Agent 层」：**没有内置对话助手，能力全部通过 MCP 暴露给外部 Agent**。你用哪个 Agent 都行，Agent 通过下面的工具了解和修改数据。

- 启动与客户端配置见 `mcp/README.md`
- 数据文件优先级：`ROUTE_DATA_FILE` 环境变量 → 稳定版 `data/routes-stable.json` → 开发版 `data/routes.json`
- 网页 ↔ 文件：开发版走 Vite 的 `/api/routes` + SSE，稳定版走 `scripts/stable-server.mjs` 的同名接口；纯静态部署没接口时自动退回 localStorage


## 约定

- 任务名写成**能执行的动作**（「持续投递并记录日志」），不要口号 / 提醒（「不要放弃」）。
- 连线：同级之间是 V 型箭头，跨层级是带线的箭头。
- 每次改完先 `npm run build` 确认类型和产物都过。

## 给 Agent 的速查

**这是什么**：纯前端行动路线工具「想拆」，把目标拆成可拖拽的树；无后端、无账号、数据在本地浏览器 + JSON 文件。

**怎么了解现状**：读 `data/routes-*.json`（路线数据）或直接调 MCP `list_routes` / `read_route`。

**怎么改数据**：用 MCP 工具（`mcp/README.md` 有完整清单）——
`list_routes` 列路线、`read_route` 读树、`apply_plan_ops` 增删改、`move_nodes` 移动、`set_done` 勾选、`manage_routes` 管路线、`focus_items` 管重点、`find_code`/`list_codes` 按码定位。改完网页自动刷新。

**注意**：改数据前先备份；所有 `board`/`node`/`id` 参数都能填 5 位码、id 或标题；数据文件里 `images` 存内嵌图片，写操作不要丢。
