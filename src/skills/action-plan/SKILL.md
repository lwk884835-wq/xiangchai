# 拆行动路线

## 默认骨架（除非用户已经说清楚结构）

```
想做成的事                ← 一级：这次要的结果（一条路线通常只有一个目标）
├ 一条并行的线 A          ← 二级：几个方向/方面，通常 3~5 条
│ ├ 具体动作 1
│ └ 具体动作 2
├ 一条并行的线 B
└ 一条并行的线 C
```

- **一级只放一个目标**：写清楚「做成什么样算成」
- **二级是并行的线**：工作/身体/生活/关系只是常见例子，按用户的事来定；
  每条线各自 `branch`，`parallel: true`，**不要串成先后顺序**
- **三级及以下才是具体动作**：每条线下面 1–4 个，写清做什么、交付什么、怎么算完成
- **不要为了一棵树好看硬造层级**：没内容就别往下拆
- 默认只做到 2–3 层；再细的等用户说「这一块帮我拆细」

## 任务名称怎么写

**必须是一个能执行的任务**：动词开头、读完知道要做什么、有交付物或完成标准。

- ✅ 「每周运动 3 次」「把毕业设计开题报告写完」「持续记投递日志」
- ❌ 「不要放弃」「保持节奏」「注意身体」「长期主义」
  这些是口号/提醒，不是任务；要改成动作。

自检：**这个标题放进待办清单，用户能不能直接开始做？**

## 用户给了缩进大纲，就按他的缩进建树

用户经常直接贴一段带缩进的结构：

```
搬去新城市
  找工作
    先改简历
    每周投 5 家
  安家
    租房
    办居住证
```

- **缩进就是层级**，不是排版：每一级缩进 → `parentId` 指到上一行
- 同一次 `update_action_plan(op="create")` 就能建完：nodes 按「父在前、子在后」排，
  子节点的 `parentId` 直接写父节点的 `title`
- 建完看返回里的 `graph`：缩进塌成一条直线 = 父级没挂上，重挂一次再回复

## 改已有的路线

- **只改内容** → `op=update` 改 title/purpose/detail
- **只改层级/换父级** → `op=update` 传 `parentId`（子树层级会自动重排），**不要整树 replace**
- **整条重排** → 才用 `op=replace`（一次性发整棵树，节点内容写短一点，太长会被输出上限截断）
- **换方向/另起一条路线** → `op=create` 时传 `board="新路线名"`：会新建一条路线，
  然后在新路线里从零建树；**不要读旧路线再复制一遍**（旧节点会和新节点串在一条线上）

## 重点清单

`op=focus` 把某几条定到顶部「重点」。这是用户自己最近想推的事，**最多 3–5 条**，别塞满。

## 常用的「改动作」工具

- 删任务：`update_action_plan(op="delete", deleteMode="only"|"cascade")`
  - only（默认）：删它和子任务，后面一步自动接回它的前一步
  - cascade：这条和后面整串一起删
- 独立成线：`update_action_plan(op="detach")` 把串行链上的任务拆出来单独一条线
- 搬任务：`move_action_nodes`
  - `position="child"`：变成目标的并行子任务（**整串**一起搬，含后面的步骤）
  - `position="before"|"after"`：插到目标前/后，只搬这一张+它的子任务（调顺序/并入别的线）
  - 传 `board` 可以跨路线搬（只支持 child）
- 勾选完成：`update_action_done`（自动级联：勾父带子、勾后带前）
- 路线本身：`manage_routes`（新建/改名/归档/恢复/删除/切换）
- 顶部临时重点：`update_focus_items`（加/勾/取消/删）

## 输出

- 说清动了哪几处（加了什么、改了什么、定了几条重点）
- 只拆了一部分就说「我只做到第二层，需要细拆告诉我」
- 不要复述整棵树，用户看得见

## 不要做

- 不要一口气把三四层全铺满
- 不要在用户收起的地方继续加东西
- 不要编造用户没说的事
